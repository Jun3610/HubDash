- 과목/공부 주제에 `notionUrl`만 남겨 V25로 다시 적용(자동 동기화 없이 수동으로 노션 필기를 과목 카드에 연결하는 용도), 이관된 과목 11개·주제 5개에 노션 페이지 주소 채움

### 막힌 것
- 취소한 브랜치의 마이그레이션이 이미 로컬 DB에 적용된 상태
→ 원인: 실제 서버 검증을 위해 머지 전 브랜치 빌드로 앱을 띄워 V25(동기화)/V26(notionUrl)이 flyway 기록에 남음. 그대로 두면 나중에 main에 다른 V25가 생길 때 체크섬 불일치로 기동 실패
→ 해결: 앱을 멈추고 한 트랜잭션에서 테이블/컬럼 제거 + flyway 기록 삭제, notionUrl 마이그레이션을 V25로 다시 번호 매겨 새로 적용

### 배운 것
- 머지 전 브랜치로 공유 로컬 DB에 마이그레이션을 적용하면, 브랜치가 취소될 때 DB까지 되돌려야 한다 — 다음부터는 머지 전 검증을 일회용 DB(testcontainers나 별도 compose 프로젝트)에서 하는 게 안전하다
- 자동화 기능은 만들기 전에 실제로 쓸 빈도를 먼저 따져 볼 것 — 필요할 때만 켜서 쓰는 개인 서버에서는 수동 연결로도 충분했다
