### 막힌 것
- 노션 Schedule 조회 결과가 페이지당 약 10만 자라 도구 출력 한도를 넘음
→ 원인: 수식 속성(Date, Month, Day of Week 등) 8개가 행마다 긴 `formulaResult://` 참조로 따라옴
→ 해결: 결과가 파일로 저장되는 걸 이용해 페이지(100건씩 4번)를 파일로 모은 뒤 필요한 필드만 파싱
- 노션 날짜가 `2026-09-24T21:00:00.000Z`처럼 Z로 와서 UTC인지 로컬 시각인지 애매함
→ 원인: 노션 date 속성은 시간대 정보 없이 보이지만 API는 UTC로 줌
→ 해결: "개강 (10시)"가 `01:00Z`, "OP6 출근"이 `21:00Z`(=다음 날 06시)인 걸로 UTC임을 확인하고 KST(+9)로 변환
- `migrate.py` 첫 실행이 사전 확인 단계에서 400으로 멈춤(데이터는 아직 안 들어간 상태)
→ 원인: 허브 링크/과목 목록 API는 `categoryId`/`semesterId`가 필수 파라미터
→ 해결: 중복 확인은 부모 테이블만 보고(자식은 부모 없이 존재 불가), 건수 검증은 부모별로 세어 합치도록 수정

- 과목/공부 주제에 `notionUrl` 추가(V26), 이관된 과목 11개·주제 5개에 노션 페이지 주소 채움(주제 설명에 임시로 넣었던 주소는 `notionUrl`로 옮김)

- 실제 노션 API로의 동기화는 아직 미검증 — 사용자가 노션 통합 토큰을 발급하고 DB에 연결해야 확인 가능

### 막힌 것
- `NotionApiClientTest`에서 응답 파싱 실패(`Cannot map null into type boolean`)
→ 원인: Spring Boot 4는 Jackson 3을 쓰고, Jackson 3은 `FAIL_ON_NULL_FOR_PRIMITIVES`가 기본으로 켜져 있어 응답에 없는 필드(블록마다 `in_trash`가 없기도 함)를 기본형 `boolean`에 넣지 못함
→ 해결: `archived`/`in_trash`/`has_more`를 `Boolean`으로 받고 `Boolean.TRUE.equals`로 판단
- `RestClient.Builder` 빈이 없음
→ 원인: Boot 4에서 RestClient 자동 구성이 별도 모듈(`spring-boot-starter-restclient`)로 분리됨
→ 해결: 스타터 추가(테스트용 `spring-boot-starter-restclient-test`도)
- 다른 세션이 같은 저장소 폴더에서 클라이언트 브랜치(`feature/web-foundation-96`)로 작업 중이라 브랜치를 바꾸면 그쪽 작업을 망가뜨림
→ 해결: `git worktree`로 별도 폴더(`HubDash-notion-sync`)를 만들어 서버 작업
