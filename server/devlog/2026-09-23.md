→ 해결: 결과가 파일로 저장되는 걸 이용해 페이지(100건씩 4번)를 파일로 모은 뒤 필요한 필드만 파싱

→ 원인: 노션 date 속성은 시간대 정보 없이 보이지만 API는 UTC로 줌
→ 해결: "개강 (10시)"가 `01:00Z`, "OP6 출근"이 `21:00Z`(=다음 날 06시)인 걸로 UTC임을 확인하고 KST(+9)로 변환

→ 원인: 허브 링크/과목 목록 API는 `categoryId`/`semesterId`가 필수 파라미터
→ 해결: 중복 확인은 부모 테이블만 보고(자식은 부모 없이 존재 불가), 건수 검증은 부모별로 세어 합치도록 수정

- 검증: Vitest 47개 통과(날짜 파싱, 주 계산, D-day, 히트맵 합산, 봉투 해제·오류 매핑), typecheck/lint/build 통과. 실제 docker 서버에 Vite 프록시로 붙여 사이드바가 쓰는 모든 목록 쿼리(정렬 필드 포함)가 200, 필수 쿼리 누락 400, 잘못된 키 401인 것을 확인하고 headless Chrome으로 데스크톱/모바일/서버 꺼짐 화면을 캡처해 봄

### 막힌 것
- 삭제 요청이 실패로 처리됨
→ 원인: 서버 DELETE는 204 No Content(본문 없음)인데 봉투가 올 거라고 가정함
→ 해결: 2xx + 빈 본문은 성공으로 처리
- 서버를 꺼도 오프라인 배너가 안 뜰 뻔함
→ 원인: Vite 프록시를 거치면 fetch 자체는 성공하고 본문 없는 502만 돌아옴
→ 해결: 봉투가 아닌 5xx는 네트워크 오류로 매핑. 프록시 대상을 `VITE_PROXY_TARGET`으로 바꿀 수 있게 해서 죽은 포트로 실제 재현
- 사이드바 "이번 주 기록" 칸이 전부 가장 진한 색으로 나옴
→ 원인: 한 주 안의 최댓값 대비로 단계를 나눠서 비슷한 날끼리는 모두 4단계
→ 해결: 최근 4주 최댓값을 기준으로 단계 계산

### 배운 것
- 서버 검증 오류 메시지는 필드 이름 없이 `"must not be blank, …"`로 합쳐져 와서 필드별 표시가 불가능 — 프론트 사전 검사는 필드 아래, 서버 오류는 폼 하단에 errorCode와 함께 보여 주기로 하고 README 결정 사항에 남김
- 서버 설정의 테마 기본값이 `"LIGHT"`(대문자 문자열) — 설정 화면도 같은 형식으로 저장해야 함
- 디자인 원본 폴더(`client/hubdash-design/`)에는 실명·학교 등 개인 정보가 들어 있고 레포가 public이라 커밋하지 않음
