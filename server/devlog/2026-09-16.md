### 막힌 것
- Request DTO의 필수 문자열 필드(`SemesterRequest.name`, `CourseRequest.name`, `AssignmentRequest.title`)에 처음에 `@NotNull`만 적용해서 빈 문자열("")이 검증을 통과하는 버그
→ 원인: 계획서 초안에 `@NotNull @Size(max=N)`으로 적어두고 그대로 구현 — hub/study가 쓰는 `@NotBlank` 컨벤션을 계획 단계에서 놓침
→ 해결: 세 필드 모두 `@NotBlank`로 수정, 컨트롤러 테스트에 blank 케이스가 400을 반환하는지 확인하는 테스트 추가

### 배운 것
- 2단계 FK 체인은 구현 패턴 자체는 1단계(study/life)의 반복이지만, "부모가 없는 경우" not-found 테스트를 **레벨마다** 빠뜨리지 않는 게 실질적인 난이도였다 — Course는 semester, Assignment는 course, 총 4가지(create/update × 2레벨) 조합을 전부 챙겨야 함
- 계획서에 필드 설계를 적을 때 "필수 문자열"이라고만 적으면 구현 단계에서 `@NotNull`과 `@NotBlank`를 혼용하기 쉽다 — 계획서 자체에 검증 어노테이션까지 명시하거나, 최소한 기존 도메인의 동일 패턴 필드를 먼저 grep해서 컨벤션을 확인하는 습관이 필요
