### 막힌 것
- 새로 만든 테스트를 넣자 기존 테스트 수십 개가 컨텍스트 로딩 실패
→ 원인: `NotionClient`, `CalDavClient`에 테스트용 생성자(RestClient.Builder 주입)를 추가해 생성자가 둘이 됐는데, 스프링이 쓸 생성자를 지정하지 않음
→ 해결: 공개 생성자에 `@Autowired`

## 2026-09-30 (이어서, iCloud 캘린더 가져오기 — 이슈 #229)
### 한 일
- `ICloudCalendarSource`: 설정에서 고른 캘린더만, 1년 전 ~ 1년 뒤를 CalDAV `REPORT calendar-query`로 읽어 동기화 틀(#228)에 연결. 계정이 있고 캘린더를 하나 이상 골랐을 때만 동작, 고른 캘린더가 iCloud에서 사라졌으면 이유와 함께 실패
- `ICalendarEvents`(ical4j 4.1.1): 시간대(TZID·UTC·시간대 없음) → KST, 날짜만 → 하루 종일(여러 날이면 끝은 DTEND 그대로), 반복 일정(RRULE/RDATE)은 기간 안에서 펼치고 EXDATE 제외, 개별 수정 회차(RECURRENCE-ID)는 같은 회차를 대신, 취소된 일정 제외. 원본 ID는 UID, 반복이면 `UID@발생 시각(UTC)`
- ical4j가 시간대 정의를 인터넷에서 받아 오지 않게 `ical4j.properties`로 끔
- 캘린더 목록 응답의 `ParkJunYoung_Schedule` 중복 경고(#227)와 합쳐, 기본은 아무 캘린더도 고르지 않은 상태
- 테스트: 변환 6종(시간대, UTC, 하루 종일 단일·여러 날, 매주 반복 + EXDATE + 개별 수정, 매년 반복 기간 한정, 취소·깨진 원문), 고른 캘린더만·1년 기간·없는 캘린더 오류, CalDAV REPORT 요청 본문(기간)과 응답 파싱. 전체 341개 통과
- 실제 경로 검증: 진짜 iCloud 계정 없이 성공 경로를 보려고 가짜 CalDAV 서버를 띄우고 API를 그 주소로 실행 — 틀린 앱 암호 400, 저장, 캘린더 목록(중복 경고), 동기화 4건 추가(한 번 1 + 매주 3회), 재동기화 0건, 원본에서 1건 지우고 반복 제목 변경 → 삭제 1·갱신 3, MANUAL 321건 그대로. 끝나고 테스트 데이터와 계정 정보 삭제

### 막힌 것
- 날짜만 있는 매년 반복 일정에서 `Unable to obtain ZonedDateTime from TemporalAccessor: 2021-10-20`
→ 원인: ical4j 4는 반복을 펼칠 기간(Period)의 타입이 DTSTART 타입과 같아야 함(날짜 / 시간대 없는 시각 / 시간대 있는 시각)
→ 해결: DTSTART 타입에 맞춰 기간을 LocalDate, LocalDateTime, ZonedDateTime으로 만들어 넘김

### 배운 것
