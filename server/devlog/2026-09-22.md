### 막힌 것
- Docker Desktop이 꺼져있어 `docker info`가 실패 → `open -a Docker`로 띄우고 데몬이 뜰 때까지 폴링해서 해결
- 단순 `docker compose restart`만으로는 named volume이 실제로 살아남는지 증명이 안 됨(같은 컨테이너가 그대로 있을 뿐) → `down`(볼륨 유지)으로 컨테이너를 완전히 지운 뒤 `up`으로 다시 만들어야 볼륨 지속성 검증이 됨
- Kafka 오프셋이 진짜 보존됐는지도 애매함 — 컨슈머가 재처리해도 `RawEventConsumer`의 멱등성 가드(`status != PENDING`이면 skip)가 있어서 데이터만 봐서는 오프셋이 보존된 건지 멱등성이 막은 건지 구분 안 됨 → `kafka-consumer-groups.sh --describe`로 `CURRENT-OFFSET`/`LOG-END-OFFSET`/`LAG`를 직접 확인해서 오프셋 자체가 보존됐음을 증명

### 배운 것
- `docker compose down -v`(볼륨까지 삭제)로 완전히 초기화 상태에서 시작해 `up -d --build`로 처음부터 띄우는 것과, `down`(볼륨 유지) 후 `up`으로 컨테이너만 다시 만드는 것은 서로 다른 것을 검증한다 — 전자는 "처음부터 잘 뜨는가", 후자는 "볼륨이 실제로 지속되는가"
- 앱 이미지가 `prod` 프로파일이라 `API_KEY`/`DB_PASSWORD`에 기본값이 없음(운영에서 조용히 기본값으로 뜨는 걸 막기 위함) — compose의 `app` 서비스에서만 로컬 전용 기본값을 명시적으로 줘야 함
